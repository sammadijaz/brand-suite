# update and regeneration

Check prior manifest hashes before reuse. Changed inputs, source evidence, typography, assets, clauses or terms invalidate affected review. Store checkpoint input/source hashes, completed slots, blockers and decisions. Deliberate reuse of unchanged reviewed text requires explicit provenance; a stale PDF is not current after a Word edit.

Build never overwrites a populated output directory. update-existing checks the prior package then produces a new version directory. Automatic negotiated-Word round-trip import is unsupported: preserve the prior document, ask the user to choose a master and review/transcribe changes into the canonical model before a new build. Never discard manual clauses or silent-replace signed documents. validate-existing is read-only.

The separate render command is for unchanged canonical content whose manifest still matches. Edited models require a reviewed new input/new output, not blind reconciliation of hashes. Rerun semantic/visual checks after content, type or image changes; real reviewer evidence never carries forward automatically.
