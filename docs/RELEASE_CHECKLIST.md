# release checklist

1. Confirm all acceptance matrix gates with actual evidence.
2. Validate skill/frontmatter/resources, schemas, unit/security tests and both installed full builds.
3. Review every generated Word/HTML page and supplementary email/stamp artwork; record actual reviewer type/hash.
4. Test ZIP integrity/extraction/reopen, target read-only preservation, existing-master protection and source-independent installed resources.
5. Audit tracked files, metadata, dependencies/licences and privacy/secret canaries; exclude private prompts and raw business evidence.
6. Resolve owner through authenticated GitHub API. Create only a new available repository; no visibility change/force push/unrelated remote.
7. Push sanitized code, check actual CI, verify remote --list and installation from the public repository, fix failures.
8. Tag/publish preview release only when declared technical/publication gates pass. Verify release API and asset URLs.

Human legal/authority approval, actual email-client testing and physical fabrication are gates for business use, not invented prerequisites or achievements for publishing this synthetic skill. Never claim them complete.
